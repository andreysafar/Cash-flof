# Соответствие правил игры и реализации

Документ фиксирует, как официальные правила и бланки (`docs/rules/`)
реализованы в коде. Логика расчётов сосредоточена в
`app/src/main/java/ru/cashflow/statement/logic/Calculator.kt`.

## Финансовый отчёт 101 (`БЛАНК-101.pdf`, стр. 1)

| Бланк | Поле модели / расчёт |
|---|---|
| Зарплата | `salary` |
| Проценты | `interest` |
| Дивиденды | Σ по дивидендным акциям LONG: `shares × dividendPerShare` |
| Недвижимость (доход) | `realEstate[].cashFlow` |
| Бизнес и предприятия (доход) | `businesses[].cashFlow` |
| **Пассивный доход** | `interest + дивиденды + Σ недвиж. + Σ бизнес` |
| **Общий доход** | `salary + пассивный доход` |
| Налоги | `taxes` |
| Выплаты по ипотеке и аренда | `homePayment` |
| Кредит на образование | `eduPayment` |
| Кредит на автомобиль | `carPayment` |
| Кредитная карточка | `creditCardPayment` |
| Мелкие кредиты | `retailPayment` |
| Прочие расходы | `otherExpenses` |
| Расходы на детей | `childrenCount × perChildExpense` |
| Оплата кредита банка | `bankLoan / 10` (10% в месяц) |
| **Общий расход** | сумма всех расходов выше |
| **Месячный денежный поток** | `общий доход − общий расход` |
| Количество детей | `childrenCount` (0…3, старт 0) |
| Активы: Сбережения | `cash` |
| Активы: Акции/фонды/депозиты | `stocks[]` (кол-во, цена) |
| Активы: Недвижимость / Бизнес | `realEstate[]`, `businesses[]` (взнос, цена) |
| Пассивы | `homeMortgage, eduLoan, carLoan, creditCardDebt, retailDebt,` |
|         | ипотека объектов, `bankLoan` |
| Цель (выход из крысиных бегов) | `пассивный доход > общий расход` |

## Действия (правила 101)

| Поле/карточка на дорожке | Реализация |
|---|---|
| **День выплат** | `payday()`: наличные += месячный денежный поток |
| **Сделки** (покупка актива) | `buyProperty()`: наличные −= первый взнос |
| Продажа недвижимости/бизнеса | `sellProperty()`: наличные += цена − ипотека |
| Покупка/продажа акций | `buyStock()` / `closeStock()` |
| Сплит / обратный сплит | `splitStock()` (×2 или ÷2 количества) |
| **Кредиты** | `takeBankLoan()` кратно $1000; платёж = 10% (= /10) |
| Погашение кредита банка | `repayBankLoan()` кратно $1000 |
| Погашение долга профессии | `repayDebt()` — только полностью (по правилам) |
| **Всякая всячина** | `doodad()`: наличные −= сумма |
| **Ребёнок** | `addChild()` (максимум 3) |
| **Благотворительность** | `charity()`: −10% общего дохода; право на 1–2 кубика 3 хода |
| **Увольнение** | `downsized()`: −общий расход; пропуск 2 ходов |
| Банкротство | вручную: «Корректировка наличных» / продажа активов |

## Скоростная дорожка (`БЛАНК-101.pdf`, стр. 2)

- Начальный доход = `round(пассивный доход до 1000) × 100` (`exitToFastTrack()`).
- **ДЕНЬ CASHFLOW**: наличные += начальный доход + Σ доходов бизнесов
  скоростной дорожки (`fastTrackPayday()`).
- Цель победы: доход в ДЕНЬ CASHFLOW + $50 000 (`fastTrackWinTarget()`) или
  покупка мечты.
- Налоговая/развод/иск: −½ наличных; забота о здоровье: −½ или все наличные.

## Расширения 202 (`blank202.pdf`, `cashflow202rules.pdf`)

Базовый финансовый отчёт — тот же бланк 101. Дополнительно (экран «Опционы и
шорт»):

| Бланк 202 | Формула в `Calculator` |
|---|---|
| Опцион CALL: сумма к получению | `max(0, новая цена − strike) × кол-во` |
| Опцион PUT: сумма к получению | `max(0, strike − новая цена) × кол-во` |
| Опцион: всего оплачено | `кол-во × стоимость опциона за акцию` (списывается при покупке) |
| Опцион: счётчик кругов | `turnsLeft` (3 → 0, кнопка «Ход (опционы −1)») |
| Короткая позиция: итог | `кол-во × цена продажи − кол-во × цена выкупа` |
| Шорт: открытие | наличные += сумма продажи; закрытие: наличные −= сумма выкупа |

## Исправления и архитектура

- **Зависание на длинной игре** (накопительный баг): снимок для отмены
  кодировал состояние вместе с историей, а каждая запись истории — со
  своим снимком и всей предыдущей историей. Размер JSON удваивался с
  каждым ходом. Исправлено: снимок кодируется без истории
  (`StatementViewModel.edit`), история ограничена 60 записями,
  `StateRepository.load` отбрасывает «раздутые» файлы старых версий.
- Игра 101 и расширение 202 разделены: на главном экране — только
  обычные акции, шорт/опционы — в разделе «Расширение 202».
- Частичная продажа акций / частичный откуп шорта (`closeStock` с
  параметром `sharesToClose`).

## Спорные моменты для согласования

1. **Выход из крысиных бегов**: правило «пассивный доход должен **превышать**
   сумму расходов» реализовано как строго `>`. Если в вашей редакции `≥` —
   поправьте `Calculator.canExitRatRace`.
2. **Благотворительность**: размер платежа взят как 10% общего дохода (правила
   101). На скоростной дорожке размер/кубики могут отличаться — уточните.
3. **Налог на скоростной дорожке** реализован как −½ наличных (универсальная
   кнопка «Минус ½ наличных»).
4. **Округление пассивного дохода** для скоростной дорожки — до ближайшей
   тысячи (`roundToThousand`).

Отметьте, что нужно изменить — поправлю.
